一、产品概述

一句话定位：给独立开发者、学生开发者的「作品首秀发射台」——登记作品 → AI 一键生成全套推广物料 → 引导分平台发布 → 采集反馈 → 生成迭代建议，形成「开发-推广-反馈-迭代」的运营飞轮。

核心承诺：用户只做一件事——专注开发。推广、文案、发布、数据、复盘、迭代建议，全部由「AI 推广大师」接管。

产品形态

对话式「项目向导」界面，以聊天/引导流驱动，减少用户思考与页面跳转时间。AI 大师以导师人格推进全流程。

技术形态决策（v1.3 定稿）：本项目为 开源软件 · 桌面端应用 · 本地 SQLite 存储 · BYOK（Bring Your Own Key）。用户只需下载安装、填入自己的模型 API Key 即可使用，无需注册账号、无云端后端、数据全部留在本地。AI 能力采用「本地接入、用户自带 Key」模式（类似 DeepSeek Harness），可接入任意 OpenAI 兼容端点（DeepSeek / OpenAI / 通义 / 本地 Ollama 等）。

由此推导的产品约束：

  • 零账号：不设账号体系、不做云同步；数据主权归用户，开源社区靠可审计代码赢得信任
  • 本地优先：作品档案、发布记录、文案历史、反馈缓存、指标数据全部存本地 SQLite；支持一键导出/导入，便于备份与迁移
  • 开箱即用：安装后首次启动引导填写 API Key（Base URL / Key / 模型名），填完即用；Key 仅存本地
  • 离线可用：除调用模型 API 与平台发布外，核心流程可离线运行

产品愿景

让每一个认真做出第一个作品的年轻人，都能被「看见」，并有动力做出第二个、第三个作品。解决独立开发者生态中「作品发布即沉没、开发热情消退」的系统性问题。

二、目标用户与核心场景

🎓 高中生开发者
利用课余时间开发小应用/小游戏，时间零散有限。缺推广经验，缺时间研究渠道，作品做完即搁置。
🎓 职校/高职学生
偏实操导向，能做出作品但普遍不会营销与运营。需要「照做就能发布」的极简指引。
👨‍💻 独立开发者
一人公司模式，时间即成本。需要自动化推广 + 数据化运营，把精力投入产品本身。

典型场景

  • 学生花了 3 个月做出第一款 Android 应用，发布到应用商店后无人问津，不知道接下来该做什么。
  • 独立开发者做出了工具，但不会写宣传文案、不会做演示视频、不知道发到哪些社区。
  • 作品在 GitHub 有零星 star，但用户反馈散落在评论区，无法判断该修什么、该加什么。

五、功能架构（六大模块）

M1 · 自动化多平台文案生成 AI 全包
输入项目一句话+功能列表，自动生成各平台适配文案：B站标题党、小红书种草体、GitHub 技术介绍、V2EX 讨论帖、Product Hunt 英文介绍、应用商店 ASO 关键词。
产出：N 平台文案包 · 可一键再生成/改风格
M2 · 冷启动策略引擎 ★ 核心
根据作品类型（工具/游戏/应用）、技术栈、目标用户，生成个性化冷启动计划：渠道优先级排序、首 100 个种子用户获取路径、72h 行动清单。
产出：个性化冷启动路线图（可执行动作，非理论文章）
M3 · 一键发布与平台打通 AI 排期 · 用户点发布
「平台连接中心」：点击平台图标 → OAuth 授权/扫码 → 打通状态点亮。按 L1 直发 / L2 跳转分层实现（见第七节）。
产出：多平台发布计划 · 单点发布/批量发布
M4 · 反馈采集与 AI 分析 AI 全包
每日增量抓取各平台评论/评分/Issue，AI 聚类归因，输出 Bug 清单（含复现路径、影响面、修复难度）、功能需求排序、情绪趋势。
产出：运营周报 · P0/P1/P2 迭代清单
M5 · 数据看板 ★ 反馈闭环
追踪推广效果：各平台曝光/点击/转化/下载/star、评论情感趋势、渠道对比。AI 主动报喜里程碑（第 1 个 star、第 1 条好评）。
产出：实时数据看板 · 里程碑推送
M6 · 社区与资源库 ★ 生态
成功案例库（学生/独立开发者 0→1 全过程复盘）、工具推荐（推广/素材/自动化工具）、榜单与成长路径。UGC 与官方内容共建。
产出：案例库 · 工具库 · 榜单
视频创作定位：短视频创作（录屏引导式）是 M1 文案生成的自然延伸，也是当前最重要的推广抓手——已作为独立核心模块，详见第六节。

六、录屏引导式短视频创作（★ 核心差异化模块）

为什么必须是短视频：当前是短视频推广时代——没有短视频，作品首秀几乎等于没有传播。对学生与独立开发者而言，录屏是他们唯一真实、零成本、零门槛的素材来源（没有剪辑能力、没有现成画面、时间有限）。因此「AI 引导录屏 → 自动做成多版本推广视频 → 跟读配音 → 本地保存 → 进入发布」是本产品最核心的差异化模块。

6.1 核心流水线（8 步，全流程 AI 引导，用户不被卡住）

  1. 启动录屏：AI 发起 → 浏览器弹出屏幕捕获 → 用户选择产品窗口（本地程序 / 网页均可）→ 自动开始录制
  2. 引导演示：AI 分 5 步脚本引导操作（打开首页停留 3 秒 → 进入核心功能 → 完整操作一次 → 展示结果 → 回到首页），每步有进度条与提示，实时计时
  3. 停止录制：原始录屏本地保存（webm），用户全程零剪辑负担
  4. 智能拆条：画面差异 + 操作停顿检测自动切出 N 个镜头（本地可选接入视觉模型打标签，自动识别「首页 / 功能 / 操作 / 结果」）
  5. 多画幅多版本：同一份素材重组为 4 个版本（见 6.2 版本矩阵），自动适配横竖屏平台
  6. 多文稿：每个版本独立 AI 生成文稿，可换风格、可编辑
  7. 跟读录音：真人对着文稿念稿录音（规避 AI 声音克隆合规风险），每个版本独立保存
  8. 合成交付：对齐配音与字幕 → 套用模板与品牌色 → 渲染多版本成片 → 本地保存 → 进入发布计划

30s 种草竖屏 9:16720×1280镜头 1·2·3·4小红书 · 视频号

  • 有 GitHub 仓库：自动抓取 README / 头像 / 截图，录屏引导从「打开仓库或在线 Demo」开始
  • 只有截图：截图串联 + 缓慢缩放（Ken Burns 运镜）生成视频
  • 连截图都没有：AI 文生图 + 排版生成示意画面，配音走 AI 兜底

七、多作品管理（作品库 + 主推队列）

关键认知：学生 / 独立开发者往往不止一个作品。多作品管理的核心不是「多存几个作品」，而是帮用户决定「现在该推哪个」——时间有限，多个作品同时大力推广会精力与流量双分散，反而全都不温不火。因此引入「作品库 + 主推队列」两层机制。

7.1 两层结构

  • 作品库（全局层）：所有作品以卡片呈现，每卡 = 作品完整档案（类型 / 生命周期状态 / 关键指标 / 下一步动作），一眼看清「哪个在跑、哪个要处理」，支持一键新增作品
  • 单作品工作区：点卡片进入后即现有的全流程向导（登记 → 物料 → 发布 → 看板 → 迭代），互不干扰

7.2 作品生命周期状态机

状态含义AI 干预程度
待启动已登记、未推广等待进入主推队列
首秀中正在做首次推广全力引导（录屏、物料、发布）
运营期持续推广 + 数据跟踪自动回复、定期内容、运营周报
稳定期已有稳定用户群日常维护，释放主推位
已归档暂停推广可随时唤醒重启

7.3 主推队列（灵魂机制）

同一时间 AI 只安排 1 个主推（全力投入，素材与物料优先供给）+ 若干挂机（自动回复、每周 1 条内容，不抢主推资源）+ 排队（等待唤醒）。主推作品进入稳定期后，AI 自动切换下一个——连「推哪个」都由 AI 决定，用户只需专注开发。

7.4 反馈与数据按作品归集

  • 每个作品的反馈、数据看板、迭代清单完全独立，互不混淆
  • 全局总览：所有作品一屏对比（曝光 / 转化 / 反馈量），AI 自动识别「哪个值得加注」

7.5 素材与模板复用

品牌色、模板、风格库跨作品复用，第二个作品开始的物料成本骤降。

八、交互设计：对话式项目向导

产品以「AI 大师」导师人格推进，用户全程被动引导，减少思考与跳转。主对话流如下：

环节用户动作AI 大师动作耗时
1. 交付作品丢一个 GitHub/下载链接 + 一句话介绍登记作品档案≈2 分钟
2. 智能诊断确认/修正定位、亮点、目标人群、一句话卖点自动
3. 物料生成点「生成」生成文案包 + 落地页 + 演示视频 + 海报≈3 分钟
4. 发布计划点「按计划发布」72h 渠道排期，逐个引导发布用户点 N 下
5. 数据跟踪只看采集数据，主动报喜里程碑后台自动
6. 迭代建议拿清单开写每周输出 P0/P1/P2 迭代清单每周 1 分钟
效率原则：授权一次长期有效、发布确认极简化、一切跳转最短路径。用户永远不需要离开向导去学习「如何做」。

九、平台打通策略（L1 / L2 / L3）

「点击图标直接打通」是核心体验目标，但需按平台开放能力分层实现：

层级策略覆盖平台（示例）说明
L1官方 API 直发 本地 OAuth 授权（Device Flow / 本地回调），Token 仅存本地 GitHub（release/issue）、Product Hunt、Google Play / App Store、X/Twitter（受限） 全自动，体验最好。需在平台开发者后台完成应用注册与权限申请。
L2AI 备料 + 一键跳转 生成好文案/图片 → 复制到剪贴板 → 自动打开平台发布页 → 粘贴发布 抖音、小红书、B站、知乎、微博、掘金等国内主流内容平台 规避个人开发者拿不到发布 API、以及自动化发帖风控问题；用户跳转与思考时间近零。
L3浏览器自动化兜底 RPA 模拟操作创作者后台 无 API 且有条件的平台（如部分社区、私信回复） 参考开源方案（PostFlow、social-auto-upload 等）。页面更新需维护，且有平台 ToS 风险，默认降级使用。
关键认知：国内主流内容平台的「视频/图文发布 API」普遍要求企业资质认证（如抖音投稿能力需审核、小红书发布无公开 API），个人开发者无法全自动。因此 L1+L2 混合是最务实架构——官方 API 能直发的直发，不能直发的把用户动作压缩到「点一下粘贴」。
本地化原则：所有平台授权 Token、发布凭据一律只存本地（SQLite 加密存储或系统钥匙串），随应用安装在用户机器上，绝不经过任何第三方服务器——与「无云端后端」的桌面端形态一致。桌面端 L1 直发通过本地 OAuth 完成授权。

注：平台能力与开发者政策实时变动，产品侧以「平台连接中心」统一封装，按需适配，不因单平台政策变化影响整体体验。

十、反馈采集与 AI 分析引擎

10.1 采集分层

反馈源采集方式可行性
GitHub Issues / star / release 评论官方 REST API✅ 全自动，无门槛
Google Play / App Store 评分评论商店官方 Developer API✅ 全自动（需开发者账号）
抖音评论开放平台评论管理 API（需申请能力）⚠️ 有条件
B站评论开放平台/接口⚠️ 需申请
小红书评论无官方 API（社区 MCP/逆向方案）⚠️ 半自动，有风控风险
私信/站内信各平台消息接口⚠️ 多数受限

10.2 AI 分析产出

  • 问题聚类：多人反馈同一问题自动归并为单条高优事项
  • Bug 清单：复现描述 + 影响面 + 修复难度评估
  • 需求洞察：Feature Request 排序（想要的功能）
  • 情绪趋势：正负面比例变化，判断口碑走向
  • 迭代路线图：P0/P1/P2 优先级清单，直接交付开发
产品原则：分析结论「喂给用户」而不是「给用户看」——AI 直接说人话：「本周 87 条反馈，3 人说导入卡死（P0），2 人想要暗色模式（P2），建议先修前者。」

十一、冷启动策略引擎（★ 解决最头疼问题）

冷启动（0→1 用户获取）是独立开发者最痛的环节。本模块不是理论文章，而是个性化可执行动作：

  1. 作品画像：类型（工具/游戏/应用）× 技术栈 × 目标人群 × 分发平台
  2. 渠道优先级：按「用户密度 × 获取难度 × 即时反馈」排序（如工具类优先 GitHub/V2EX/即刻，游戏类优先 B站/抖音/itch.io）
  3. 首 100 用户路径：种子用户获取策略（社区潜水定向邀请、站内首发帖、学习/教学场景切入）
  4. 72h 行动清单：逐日逐渠道的发布节奏，用户照做
  5. 策略复盘：结合数据看板反馈，自动调整下一轮渠道侧重

十二、社区与资源库（★ 生态）

  • 成功案例库：学生/独立开发者 0→1 全过程复盘（做了什么、发了哪、数据如何、转折点），UGC 征集 + 官方精选
  • 工具推荐库：推广工具、素材工具、自动化工具分类榜单
  • 成长路径：从「首个作品」到「稳定用户群」的成长里程碑体系，配合成就激励
  • 社区价值：案例即获客（用户看到别人成功 → 想用本产品）、即留存（持续学习）、即传播（案例可分享）

十三、技术架构

总体架构：纯本地桌面应用，无服务器、无账号、无云后端。所有数据落本地 SQLite，所有 AI 能力走用户自备 Key（BYOK）。
层组件说明
桌面壳Electron / Tauri（桌面端应用壳）跨平台安装包；Tauri 更轻量（首选），Electron 生态更全（备选）
UI对话式向导界面（React/Vue，承接现有交互原型）项目向导 + 平台连接中心 + 数据看板 + 设置（API Key 管理）
AI 接入层BYOK LLM 接入（OpenAI 兼容 Chat Completions 协议）用户配置 Base URL / API Key / 模型名即可接入 DeepSeek、OpenAI、通义、本地 Ollama / LM Studio 等；Key 仅存本地
AI 编排LLM 编排（文案生成 / 诊断 / 聚类分析 / 策略生成）多 Agent：文案 Agent、冷启动 Agent、反馈分析 Agent、报喜 Agent
平台连接层本地 OAuth + 各平台适配器L1 API 适配器（本地 OAuth，Token 存本地）/ L2 深链与剪贴板 / L3 RPA 兜底
采集层本地定时任务 + 增量去重评论/评分/Issue/数据指标；应用在后台时按需轮询
数据层SQLite（本地单文件）作品档案 / 发布记录 / 文案历史 / 反馈库 / 指标库；统一反馈模型与指标口径
交付层本地物料生成管线（详见第六节 6.5）文案包 / 落地页（模板引擎）/ 录屏引导式短视频（拆条 → 多版本 → 渲染）
视频选型：演示视频用 Remotion（React 写视频，代码化渲染，适合自动化按项目信息生成），而非改造完整开源剪辑器——OpenCut/Clypra 面向「人剪」，不适合程序化批量生成。桌面端渲染在本地执行，无需服务端。

十四、MVP 范围与里程碑

阶段范围验证目标
MVP 1.0 桌面端应用壳（安装即用）· 首次启动 API Key 设置（BYOK）· 对话式向导 · 作品登记（本地 SQLite）· 多平台文案生成（接真实 LLM）· 冷启动 72h 计划（可编辑）· L2 一键跳转发布 · 发布队列与结果回填 验证「登记→生成→发布」是否顺畅，用户是否愿意走完流程；BYOK 配置是否够简单
MVP 1.5 落地页生成 · GitHub/商店 API 直发（L1，本地 OAuth）· 数据看板 v1 · 里程碑报喜 · 录屏引导 v1（录屏 + 单版本竖屏成片）· 多作品作品库 v1（卡片管理 + 主推队列）· 数据导出/导入 验证反馈闭环雏形 + 录屏成片是否顺畅
MVP 2.0 反馈采集 + AI 分析（周报/迭代清单）· 多画幅多版本渲染（Remotion 本地渲染）· 开源发布与社区案例库 验证「运营飞轮」+ 短视频多平台分发是否转起来

建议 MVP 1.0 优先做「桌面壳 + BYOK 接入 + 文案生成 + 冷启动计划 + L2 跳转发布」——成本最低、见效最快；录屏单版本成片放入 1.5（用户最迫切想要的实物），多画幅多版本渲染与开源社区放入 2.0。

十五、风险与合规边界

风险应对
平台 API 政策变动 / 个人开发者拿不到发布权限L1/L2 混合架构，单平台变化不影响整体；平台连接中心统一封装适配
自动化发布触发平台风控限频、延迟发布、优先官方 API；L3 兜底标注 ToS 风险
反馈采集涉及用户隐私只采集与作品相关的公开评论/数据，遵守平台 ToS 与个人信息保护要求
用户授权范围信任问题授权时明示权限范围，发布动作保留用户确认；Token 仅存本地，可随时撤销
AI 文案同质化 / 平台判定营销文案风格模型多版本 + 人工微调入口
BYOK 依赖用户自带 Key（成本自担 / 不同模型效果差异）支持多端点与模型自由切换、用量与成本提示；提示词精简以控成本
开源软件信任与二次分发代码开源可审计、数据全本地不收集；提供官方签名安装包与校验
录屏 / 录音涉及用户隐私全程本地采集、仅用户主动上传；授权时明示用途与保存范围，可随时删除
